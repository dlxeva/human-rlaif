# 安装、恢复与升级

## 给执行安装的 agent

先阅读本包和脚本，遵守宿主权限。安装授权只涵盖公共技能文件；私人工作目录的位置、写入范围和第三方发送另行确认。

将本独立仓库完整内容作为 `human-rlaif` 技能目录放到宿主支持的 Skills 位置，确保仓库根目录 `SKILL.md` 保持在技能目录顶层。目录名和 frontmatter name 均为 human-rlaif。宿主路径以当前官方说明为准，本包不会自行改写 AGENTS.md、全局规则或其他技能。

复制前确认宿主和目标绝对路径。未指定目标时，可以建议宿主支持的候选目录，但不能把“帮我装起来”当作对该候选目录的确认。先检查目标是否存在；存在时停止复制，保留原文件，说明情况并请求选择新目录或另行授权升级，不覆盖或移动已有技能。若目标已在本会话明确授权范围内，无需重复确认。合成测试只允许在测试沙盒内安装，禁止触碰真实宿主配置。

报告三种状态：公共文件已放置；宿主已识别技能；实际首轮已完成。逐项验证，禁止合并宣称“全部可用”。建议明确调用一次 human-rlaif 检查激活，再开始 onboarding。

## 能力检查与降级

- 无持久文件读写：使用会话内流程，给出可复制记录。提醒跨会话需要用户提供状态。
- 有文件读写、无 Python：按照模板在获准的私人目录手工创建文件，遵守不覆盖和 Git 隔离要求。
- 有 Python：使用 workspace.py，运行 doctor 验证结构。doctor 只验证本地文件，不验证宿主自动加载、真实同意或学习效果。
- 有调度工具：只有用户明确要求时才设置提醒。Markdown 本身不会定时执行。

首次确认一个领域、参与规范和私人目录；每轮只问影响启动的最小问题。HUMAN.md 确认状态从 draft 改为 accepted 后开始约定的长期模式；在此之前可以继续普通帮助。

## 私密与恢复

私人工作区放在所有 Git 工作树之外，脚本拒绝已存在的符号链接路径。支持的 POSIX 环境下创建目录 0700、文件 0600。文件权限不能防止所有宿主同步或云模型传输；用户需要了解所在环境的数据处理方式。

init 可重复调用，仅在标记和必需文件完整时报告已存在；未知或残缺目录拒绝覆盖。遇到残缺目录，先检查并备份，由用户选择新目录或人工恢复。record 以独立 JSON 事件保存，重复 ID 拒绝。脚本不直接改 HUMAN、BASELINE、STATE 或 JOURNAL。

新会话要实际读取同一个私人目录，按需加载。备份由用户选定渠道；默认不上传、不同步至公共仓库。

## 升级与移除

升级前备份公共技能目录和用户获准的私人状态；替换公共目录，保留私人文件。schema_version 变化需要显式迁移方案，当前只支持 1。不同版本不静默覆盖。

移除技能时只删除公共技能目录。私人记录由用户决定保留、导出或删除。个人规范与私人数据不会作为上游贡献回传。
