# 运行协议 v0.1.1

## 最小循环与人的责任

从一个真实判断开始：人保存原始判断和结果概率，AI 给一个关键挑战，双方约定新题复测日期。完整 HUMAN 与基线表在 2–3 个小循环后由 AI 起草、人确认；延期的是长表，不是人的责任。

从第一轮起，人提供真实且相关的材料，区分亲历、转述、假设、愿望与未知；在反馈前暴露自己的判断与卡点；说明关键采纳、拒绝与取舍；对现实行动及结果返回负责。允许粗糙口语、“不知道”、合理保密与持续分歧，字数、术语和文采不作指标。AI 自己负责读取获准来源、查证、完整分析与纠错，不能把框架遗漏转嫁给人。

将“更高定位”写成想练习的新增结果责任，并列出现实权限、资源和价值边界；它不是已取得的身份。协议变更记录“旧条款 / 拟改条款 / 理由 / 影响 / 本人确认 / 日期 / 事件 ID”。未确认保持 draft 或 proposed，不能由 AI 或脚本代替本人接受。

## 每轮开始与到期项

先定位获准私人工作区，执行 `due --workspace /absolute/private/path`，把到期事件及原约定日期简报给人。没有 Python 时按 [事件格式](event-schema.md) 人工检查；无法读取时报告 unknown。没有工作区就使用用户提供的续接记录，不假装有跨会话记忆。

`due` 比较带时区的 `due_at` 与当前时间，列出尚无有效 `retest_of` 完成记录的到期项。到期不等于已完成；用户决定复测、改期或先赶交付。实际复测另存事件、引用原 ID，原预测与日期不覆盖。需要改期时保留原约定，并明确新约定来源；没有改期工具时人工记录，不暗中移动原日期。

每轮开始检查是 Agent 执行约定，脚本不会自动加载技能或发送通知。只有用户明确要求并且宿主支持时才另设提醒。实际宿主启动是否执行过检查必须另有观察，不能用单元测试替代。

## 预测校准：主指标

每次可评估判断写一个二元、可观察、有限时点的预测。例如“截至 10 月 24 日 09:00 UTC，改版读完率高于原版”，而不是“项目会更好”。作答前锁定观察口径、成功条件与评分标准，人的首稿在 AI 反馈前保存；预测成立概率 `confidence` 用 0–100%，与“我觉得自己进步了”分开。不知道就不造数，记录缺失原因和未决状态。

事件中的 `prediction_type`、`prediction`、`confidence`、`resolution_criteria` 一起保存。首次预测保留原值；AI 反馈后改变看法可以另记，但不能用新概率覆盖原预测，也不能把后见之明算进首稿。预先选择固定任务族和记录规则，不只保留成功或高把握样本。

真实结果回来后另建事件，以 `resolves_prediction` 指向原预测 ID，`outcome` 为 true/false，附可检查来源并标 externally_checked；同一预测只解答一次。指标分歧、行动未执行、结果模糊或来源不可检查时保持 unresolved，不能把 unknown 填成 false。脚本检查来源字段，不核验其真实内容；人仍负责实际核查。若后来发现已存证据错误，保留原记录与纠错说明，暂不把有争议样本当可靠结论，不暗改原数据。

`calibration --workspace /absolute/private/path` 输出：

- 可计分样本数与未决数，明确每项分母；不同任务族、时段或帮助条件比较时保留这些条件。
- 命中率：事先概率 ≥50% 视为预测发生，低于 50% 视为预测不发生，与实际结果对比。它是方向指标，不能单独代表校准。
- 平均 Brier 分数：令 p = confidence/100、y = 1 或 0，取 `(p-y)²` 的平均值，越低越好。概率分档同时对比平均预测概率与实际发生率。

无已核查结果时不输出虚构的零分或“100%”。短期成绩改善还需考虑任务难度、样本选择、外部经验、AI 帮助和偶然因素；保留失败、未执行和无收益案例。

## 基线、独立性与评阅

练习时先留最低限度的原始判断与时间；完整基线之后从已有事件整理，缺失历史仍为 unknown。正式 assessment 在作答前锁定任务族、材料、时间、rubric_ref、辅助条件与评阅方式。保存用户原话，AI 润色稿另列。

优先交给另一模型或真人盲评，隐藏此前 AI 结论、干预条件和期望结果，同时记录具体盲化范围。向第三方发送材料前确认对象、材料及权限；没有许可就不发送。同一 AI 自评明确记 `ai_self_review`，不同模型但看到旧评分也不算盲评。评分者、标准版本、独立表现、协作成果、协作控制与主观把握分别记录，不能互相代替。

隔离标记：clean / partial / contaminated / unknown。只有新材料、旧答案不可见、首稿前没有目标提示、原始首稿保留时才可用 clean。新会话不自动等于隔离：宿主记忆、HUMAN 的策略条款、模板、旧对话都可能泄漏。评估只加载行政约定与必要材料，不能先给示范再称独立。

延迟复测使用新材料，记录实际间隔、难度、模型与帮助变化。`retest_interval` 是计划间隔，不能代替实际日期证据；`retest_of` 只是关联字段，不能证明真实人已做题。真实 ≥7 天循环必须经历真实时间，并取得原始判断、挑战、行动、结果与新题复测记录。

## 挑战、现实反馈与停止

默认每轮只提出一个最有价值的表达、证据、反例、资源取舍或迁移挑战。说“不知道”时降低难度、给提示或示范并记录帮助；用户拒绝时核对理由而不是追加压力。用户赶交付、疲惫或不适时切换 production 或暂停，正常帮助继续。

行动前写预期、反证条件、负责者与观察时间。现实反馈可以来自获准接触的利益相关者或可检查结果；模拟角色和多个 AI 一致意见只供准备。结果回来时区分执行偏差、观察结果与因果解释。

阶段复盘也检查 AI 是否查源、遗漏结构、迎合、代做目标技能或移动标准。规则允许修改，旧版和理由保留。维护成本过高或持续无收益时简化、暂停或换方法。

## 事件、摘要与恢复

完整字段与兼容规则见 [事件格式 v2](event-schema.md)。事件文件不覆盖；JOURNAL 与 STATE 只作带事件 ID 的摘要，冲突时回查原始事件并请人确认。时间顺序校验只能检查声明的时间，不证明首稿独立、真实同意或现实结果。

新会话先检查目录与 doctor，再执行到期检查，按模式加载相关资料。无文件能力提供可复制的简短续接卡。真实 HUMAN、私人事件、客户数据和未获授权的来源不提交公共 Git；脱敏导出需本人复核，上传另行授权。
